## 1. 摘要

StoryWeave（中文名：墨织）是一款开源的小说构思与创作软件。当前推出桌面版。作者用它把人物、关系、事件、故事线、时间线和章节放在同一个项目里，并在这些对象之间跳转。

它按单机软件来做：不建立账号，也不在开发者的服务器上保存用户信息或小说正文。项目留在作者自己的电脑上。作者若要多端互通，可以导入项目文件、连接自己的远端仓库，或自行配置；这些通路可以接到插件槽上。

第一版要让一位作者在不联网的情况下，稳定地整理一部结构复杂的长篇。移动端留到桌面版之后再评估。模型自动改写不进入这一版。

一句话：把人物、关系、事件、时间线与章节脉络编织在一起，让长篇故事可视化、可追踪、可持续创作。

## 2. 要解决的问题

长篇构思通常散落在聊天记录、表格、便签和正文文档里。作者记得住单个人物，却很难同时回答这些问题：

- 这两个人此刻是什么关系，这个关系从哪件事开始变了？
- 这条支线里的事件，按故事内时间该排在哪里，又在哪一章被讲出来？
- 删掉一个人物之后，哪些关系和章节引用会跟着断掉？
- 应用异常退出或换一台电脑时，这些资料还在不在？

通用笔记软件能保存文字，不能把上述对象连成可查询的结构。通用白板能画线，不能作为人物和事件的权威数据。墨织要做的是这层结构，以及围绕它的写作工作台。

## 3. 产品原则

1. **单机可用。** 打开、编辑和保存不需要账号，软件本身不保存用户信息。
2. **作者拥有数据。** 项目可以备份、导出和导入。多端互通走作者自己的文件、远端仓库或插件配置。
3. **结构服务于写作。** 人物和事件保持结构化；正文和笔记仍用 Markdown 原文写作。
4. **图谱是入口，不是海报。** 从节点和连线能打开对应的人物、关系、事件和章节。
5. **AI 可选且后置。** 核心闭环不调用模型。以后接入时，模型输出先进入候选，作者确认后才写入。
6. **先做可靠的小版本。** 数据不丢、关系改得动、重启还在，优先于功能数量。

## 4. 用户与场景

### 4.1 目标用户

- 正在构思长篇小说、系列小说或复杂世界观的个人作者。
- 需要维护大量角色、阵营、地点和设定的创作者。
- 需要同时追踪多条故事线、故事内时间和伏笔的作者。
- 希望资料留在本机，并能导出成通用格式的用户。

### 4.2 非目标用户（第一版）

- 需要多人实时协作的写作团队。
- 需要墨织代管账号、订阅、社区或出版排版的用户。多端互通可以走作者自己的文件和远端仓库。
- 希望模型直接决定剧情或改写正文的用户。

### 4.3 关键场景

1. **建档。** 作者新建项目，录入主要人物和他们之间的关系，关闭应用后第二天继续改。
2. **查关系。** 作者在关系图里点开一个人，看到他的资料、关系、参与事件和出场章节。
3. **排剧情。** 作者把同一批事件放进故事线，同时按故事内时间查看；章节顺序可以与故事时间不一致。
4. **写章节。** 作者为一章写 Markdown 正文，并标出本章出场人物和相关事件。
5. **找回数据。** 导入失败或异常退出后，作者回到最近一次成功保存的项目，而不是得到一份写坏的库。

## 5. 范围

### 5.1 MVP 包含

| 模块 | 作者能完成的事 |
| --- | --- |
| 项目 | 新建、打开、重命名、关闭；查看最近项目 |
| 人物 | 维护档案，并看到这个人的关系、事件和章节 |
| 关系图 | 拖动节点、建立和编辑关系、保存布局 |
| 故事线 | 建立剧情弧，把事件排进弧里并调整顺序 |
| 时间线 | 按故事内时间查看事件，并看到它在哪一章被叙述 |
| 章节与场景 | 管理章节、场景、状态和 Markdown 正文 |
| 笔记 | 记录尚未升格为正式设定的灵感和世界观 |
| 搜索 | 按标题和正文查找人物、事件、章节、笔记 |
| 数据安全 | 自动保存、备份、恢复、导出、导入 |

### 5.2 明确不做

第一版不做这些事：

- 墨织自己的账号、用户信息存储、订阅、团队权限和内容社区。
- 由墨织托管的云同步。多端互通由作者导入文件、连接自己的远端仓库，或通过插件槽自行配置。
- 移动端界面。当前只发布桌面应用。
- 出版级排版。
- AI 提取、一致性检查、自动改写。
- 插件市场、自定义字段和数据库加密。插件槽是扩展点，第一版不依赖插件就能写作。
- 把地点、组织、物品做成与人物同级的通用实体。笔记可以先记下这些内容。
- 数千节点的大图性能。MVP 以数百节点内可拖拽、可缩放、可筛选为目标。

### 5.3 后续版本

| 版本 | 增加的能力 | 完成标准 |
| --- | --- | --- |
| M2 | 可选的模型提取 | 候选结果经作者确认后才写入；关闭模型后其余功能仍可用 |
| M3 | 一致性提示、伏笔状态、关系图过滤与分组、发布流水线 | 提示只标出疑似矛盾和依据，不改作者设定 |
| M4 | 插件槽、作者自己的远端仓库鉴权、模板、自定义字段和本地加密 | 插件只在作者安装并配置后运行；远端仓库使用作者自己的凭据 |
| 桌面版之后 | 移动端 | 沿用同一套项目文件。仍不代管用户信息 |

版本的技术拆分见 [技术规划第 2、14 节](./Planning.md)。

## 6. 信息架构

应用是一个三栏桌面工作台：

```text
┌──────────────────────────────────────────────────────────┐
│ 顶栏：项目名称 / 搜索 / 保存状态 / 导出 / 设置           │
├────────────┬───────────────────────────┬─────────────────┤
│ 01 概览    │ 当前工作区                │ 选中对象        │
│ 02 人物    │                           │ 字段与关联      │
│ 03 关系图  │                           │                 │
│ 04 故事线  │                           │                 │
│ 05 时间线  │                           │                 │
│ 06 章节    │                           │                 │
│ 07 笔记    │                           │                 │
└────────────┴───────────────────────────┴─────────────────┘
```

对象关系：

```text
项目
├── 人物 ──关系── 人物
├── 事件 ──参与── 人物
├── 故事线 ──排序包含── 事件
├── 章节 ──包含── 场景
│     └── 引用人物、引用事件
└── 笔记
```

关系图上的坐标、缩放和筛选是视图数据，单独保存，不写入人物档案字段。

## 7. 关键流程

### 7.1 从空项目到一张可用的关系图

1. 作者在启动页新建项目，只填写名称。描述可留空。
2. 进入人物页，新增至少两个人物。
3. 在关系图中把两人连起来，选择关系类型并写下说明。
4. 拖动节点。
5. 关闭应用并重新打开同一项目。人物、关系、说明和节点位置都还在。

### 7.2 把事件排进时间和章节

1. 作者新建事件，填写标题和故事内时间。故事内时间允许是具体日期、朝代纪年或「未知」。
2. 把人物标为参与者。
3. 把事件加入一条故事线，并调整它在这条线里的顺序。
4. 新建章节，用 Markdown 写作，并引用相关人物和事件。
5. 时间线同时显示故事内时间和「首次出现在哪一章」。两者可以不一致。

### 7.3 保存、失败和恢复

1. 编辑停止约 0.8 秒后自动保存，顶栏显示最近一次成功保存的时间。
2. 保存使用事务。失败时保留上一次成功状态，并提示作者，而不是静默丢掉这一次编辑。
3. 距离上次快照超过 15 分钟，或累计 20 次成功写入后，生成一份数据库快照。默认保留最近 10 份。
4. 导入或恢复前先自动做一份快照。作者必须先看到将要写入的内容，确认后才覆盖。
5. 导入校验失败时，当前项目保持原样。

## 8. 功能需求

优先级：P0 为 MVP 必须交付，P1 为紧随 MVP 的导入能力，P2 及以后不进入第一版验收。

### 8.1 项目

| 编号 | 需求 | 优先级 | 验收 |
| --- | --- | --- | --- |
| PRJ-01 | 新建项目。名称必填，描述可选 | P0 | 空名称不能创建；创建后立刻进入该项目 |
| PRJ-02 | 打开最近项目，并记住列表顺序 | P0 | 重启后列表仍在，最近打开的排在前面 |
| PRJ-03 | 重命名项目、修改描述 | P0 | 顶栏和概览同时更新 |
| PRJ-04 | 关闭当前项目，回到启动页 | P0 | 关闭前已完成的保存不丢失 |
| PRJ-05 | 概览显示简介、人数、事件数、章节数和最近编辑 | P0 | 数字来自当前项目，而不是写死的文案 |
| PRJ-06 | 从概览进入新建人物、新建事件、新建章节 | P0 | 进入对应页面并选中新建对象 |

### 8.2 人物

| 编号 | 需求 | 优先级 | 验收 |
| --- | --- | --- | --- |
| CHR-01 | 新增、编辑、删除人物 | P0 | 列表、详情和关系图使用同一份数据 |
| CHR-02 | 档案包含姓名、别名、身份、外貌、性格、目标、背景、备注、状态 | P0 | 字段可单独保存；空字段允许留空 |
| CHR-03 | 状态使用作者语言：在场、离场、下落不明 | P0 | 筛选可以只看其中一种状态 |
| CHR-04 | 人物详情列出相关关系、参与事件、出场章节 | P0 | 点击关联项会打开那个对象 |
| CHR-05 | 删除人物前说明后果 | P0 | 确认后删除该人物的关系；章节和事件保留，只解除关联 |
| CHR-06 | 按姓名和别名筛选人物列表 | P0 | 不区分大小写；中文按包含匹配 |

人物自定义字段放到 M4。MVP 不提供任意加字段，避免档案结构在验证前发散。

### 8.3 关系图

| 编号 | 需求 | 优先级 | 验收 |
| --- | --- | --- | --- |
| REL-01 | 每个人物对应一个节点，每条关系对应一条边 | P0 | 新增或删除后图与列表一致 |
| REL-02 | 拖动节点、缩放和平移画布 | P0 | 重启后位置、缩放和平移仍然存在 |
| REL-03 | 建立有向或无向关系。类型预设为：亲属、师徒、恋爱、合作、敌对、利用、同门、旧识、未知 | P0 | 不能把人物连向自己；类型和说明可改 |
| REL-04 | 选中节点或边时，在侧栏编辑并跳转到人物 | P0 | 双击节点进入该人物档案 |
| REL-05 | 按关系类型显示或隐藏边 | P0 | 隐藏边不删除数据 |
| REL-06 | 侧栏区分关系的故事内生效区间：当前、过去、未知 | P1 | 区间只影响资料，不要求第一版做时间播放 |
| REL-07 | 导出 PNG 或 SVG | P2 | 不作为 MVP 验收 |

「A 认为 B 是敌人」和「双方互为敌人」用方向表达。无向关系在图上不画箭头。

### 8.4 故事线、事件与时间线

| 编号 | 需求 | 优先级 | 验收 |
| --- | --- | --- | --- |
| ARC-01 | 新建、编辑、删除故事线，并标记为主线、支线、人物线或感情线 | P0 | 删除故事线不删除事件本身 |
| ARC-02 | 把已有事件加入故事线，并上移、下移 | P0 | 顺序重启后仍在 |
| EVT-01 | 新建、编辑、删除事件。事件有标题、说明、故事内时间、参与人物和参与身份 | P0 | 故事内时间可以是文本，也可以标记为未知 |
| EVT-02 | 同一事件可以出现在多条故事线 | P0 | 在一条线里调整顺序，不改写其他线的顺序 |
| TML-01 | 时间线按故事内排序展示事件 | P0 | 排序键独立于章节顺序 |
| TML-02 | 每条事件显示它第一次被哪一章叙述；尚未写进章节时明确标出 | P0 | 叙述章节与故事时间允许不一致 |
| TML-03 | 作者能改故事内排序，而不必先写一个可解析的公历日期 | P0 | 「承安三年冬」这类纪年可以保存和排序 |

伏笔的「待回收 / 已回收」放到 M3。MVP 可以用事件说明和笔记暂记，不单做一套伏笔状态机。

### 8.5 章节、场景与笔记

| 编号 | 需求 | 优先级 | 验收 |
| --- | --- | --- | --- |
| CHP-01 | 新建、排序、编辑、删除章节 | P0 | 删除章节不删除被引用的人物和事件 |
| CHP-02 | 章节状态为：构思中、草稿、修订中、完成 | P0 | 概览能数出未完成章节 |
| CHP-03 | 章节正文使用 Markdown 原文编辑，并排预览 | P0 | 保存的是 Markdown 原文，而不是另一套富文本 |
| CHP-04 | 章节关联出场人物和事件 | P0 | 从人物页能回到这些章节 |
| SCN-01 | 章节下可加场景，场景有标题、摘要、排序和故事内时间 | P0 | 场景顺序独立于项目级时间线 |
| NOT-01 | 笔记有标题、正文和标签 | P0 | 可被全局搜索命中 |
| NOT-02 | 把笔记升格为人物或事件 | P2 | 不作为 MVP 验收；MVP 由作者手工新建 |

### 8.6 搜索、保存与迁移

| 编号 | 需求 | 优先级 | 验收 |
| --- | --- | --- | --- |
| SRC-01 | 一个搜索框覆盖人物姓名与别名、事件、故事线、章节和笔记的标题与正文 | P0 | 结果分组显示；点击结果打开对象 |
| SRC-02 | 搜索在本地完成 | P0 | 断网时结果与联网时一致 |
| DAT-01 | 自动保存，顶栏只在成功写入后更新状态 | P0 | 输入过程中不因为保存而打断光标 |
| DAT-02 | 按第 7.3 节的规则做快照、恢复和失败回滚 | P0 | 用损坏文件导入时，原项目哈希或备份对比保持不变 |
| DAT-03 | 导出 JSON 项目包，包含结构数据和 Markdown 正文 | P1 | 导出后再导入，人物、关系、事件、章节正文和布局一致 |
| DAT-04 | 导出 Markdown，正文和笔记可读 | P1 | 文件可在外部编辑器打开 |
| DAT-05 | 导入前预览变更，并处理标识冲突 | P1 | 没有确认对话框就不会写入 |
| DAT-06 | 启动时如果上次退出不完整，提示恢复最近快照 | P0 | 作者可以拒绝恢复并保留现场以便排查 |

MVP 的权威存储是一份 SQLite。结构化数据和正文都先写进库里，导出时再生成 Markdown 和 JSON。不在第一版同时维护「数据库一份、文件夹一份」的双写。

原型里的「导出 JSON」只用于演示结构，不是最终项目包格式。

| SET-02 | 默认使用宣纸主题 | P0 | 正文与背景对比满足长时间阅读 |

## 9. 交互要求

- 当前版本是桌面应用。工作区按三栏使用。移动端以后再做，这一版不改成手机布局。
- 顶栏只放会工作的动作。没有实现的撤销、分享或发布按钮不占位置。主题切换、导出和设置属于会工作的动作。
- 删除一律先说明会连带影响什么，再要求确认。
- 空项目显示下一步：新建人物。不使用与当前项目无关的示例数据充数。
- 关系图的拖拽和点击要分开：轻微移动仍视为选中，明显拖动才改变位置。
- 错误提示说明作者可以做什么。数据库和文件错误不把本机绝对路径写进普通提示以外的日志全文；设置页可以显示项目路径，因为那是作者要找的位置。

可点击的界面原型覆盖概览、人物、关系图、故事线、时间线、章节、笔记和搜索。原型数据是一部名为「北境剑录」的示例项目，用来演示对象如何相连；它不会写入磁盘。主题选择记在浏览器里，项目数据不记。

### 9.1 外观

工作台按现代界面来做，材料取自水墨，不做成仿古窗格或纹样装饰。

- 两套主题可以随时切换：**宣纸**是浅色默认，**夜墨**是深色。选择记在本机。
- 标题和正文用宋体，导航、按钮和表格用无衬线，方便扫读。
- 关系画成圆角曲线。界面圆角统一，不用直角网格当装饰。
- 颜色以墨和纸为主。朱砂只用于选中、焦点、危险操作和标记。
- 产品图标是原创标记：两缕墨线交织一次，交点一颗朱砂。图标里不放文字，也不借用现成的印章、山水或龙纹。文件是 `Docs/assets/icon.ico`，圆角外侧的四角透明。`Docs/assets/icon.png` 是同一张图，供页面显示。

| --- | --- | --- |
| NFR-01 | 平台 | 当前发布桌面版。开发阶段同时验证 macOS 与 Windows 的安装和启动。Linux 不阻塞 MVP。移动端不在这一版 |
| NFR-02 | 离线 | 除作者自行开启的远端仓库、插件或模型外，全部 P0 功能离线可用 |
| NFR-03 | 性能 | 普通增删改查无明显卡顿。约 300 个节点的关系图可以拖拽、缩放和按类型筛选 |
| NFR-04 | 保存 | 自动保存合并连续输入，不在每个按键上写盘 |
| NFR-05 | 完整性 | 导入失败、迁移失败或进程退出时，已成功提交的数据仍可打开 |
| NFR-06 | 隐私 | 不保存用户账号或个人资料。默认不上传正文，不采集遥测。日志不记录密钥和正文全文 |
| NFR-07 | 权限 | 文件访问限制在作者选定的项目和导出位置内 |
| NFR-08 | 可访问性 | 导航和主要动作可用键盘到达；焦点可见；正文与背景保持可读对比 |

冷启动以「普通开发机器上数秒内进入最近项目或启动页」为工程目标，不在本需求里写死毫秒数。

## 11. 已确认的产品决策

这些决定用来结束规划阶段的分支，实现时直接采用。

| 议题 | 决定 |
| --- | --- |
| 名称 | StoryWeave，中文名墨织。公开发布前核对 GitHub 仓库名、包名和商标 |
| 形态 | 当前为桌面应用。移动端在桌面版之后评估 |
| 许可证 | MIT |
| 编辑器 | Markdown 原文编辑，并排预览。实现选用 CodeMirror 6。不并行做所见即所得 |
| 存储 | 一份 SQLite 作为唯一权威来源。正文保存在库内。Markdown 文件夹模式以后再评估 |
| 服务端 | 不设独立后端。本地文件、数据库和窗口由桌面端的 Rust 层完成 |
| 图谱 | 节点位置单独存储 |
| 删除人物 | 同时删除关系；保留章节和事件，并解除关联 |
| 备份 | 最近 10 份快照；导入和恢复前强制再做一份 |
| AI | 不进入 MVP。以后也必须先确认再写入 |
| 用户信息 | 不存储。没有账号体系 |

| 外观 | 宣纸为默认，可切换夜墨。图标是两缕交织的墨线，交点一颗朱砂 |

## 12. 成功标准

MVP 可以发布预览版，当下面几件事都成立：

- 作者能在 30 分钟内，离线建成一个不少于 5 个人物、若干关系和两条故事线的项目。
- 重启应用后，档案、关系、布局、事件顺序和章节正文都还在。
- 章节的叙述顺序可以和故事内时间不一致，而且两种顺序都能看懂。
- 用一份损坏的导入文件操作后，原项目仍能打开。
- macOS 和 Windows 各完成一次真实安装、启动和上述保存验证。

发布前的工程清单以 [技术规划第 15 节](./Planning.md) 为准。

## 13. 衡量

第一版不设日活或留存目标。看这些使用结果：

- 预览版作者是否能不用口头讲解完成第 7.1 和 7.2 节的流程。
- 是否出现「关系图和人物档案不一致」或「重启后正文丢失」的报告。
- 作者导出的项目能否在第二台电脑上打开并核对。

这些问题比安装量更能说明 MVP 有没有做成。

## 14. 仍待核对的事项

- 公开发布前检索「StoryWeave」「墨织」在软件仓库、包名和商标上的冲突。
- 预览版收集真实项目后，再决定自定义字段、地点和组织要不要升格为正式实体。
- 关系图导出 PNG 或 SVG 是否进入紧随 MVP 的版本。

## 15. 术语

| 术语 | 含义 |
| --- | --- |
| 项目 | 一部作品的全部结构化资料和正文 |
| 人物 | 故事中的角色档案 |
| 关系 | 两个实体之间的一条语义连接，可以有方向 |
| 事件 | 故事里发生的一件事，拥有自己的故事内时间 |
| 故事线 | 一组按叙事目的排序的事件，例如主线或人物线 |
| 故事内时间 | 事件在虚构世界中的先后，不等于章节顺序 |
| 叙述顺序 | 事件在章节正文里被讲出的顺序 |
| 快照 | 一份可恢复的数据库备份 |
| 候选 | 模型给出、尚未写入正式数据的提取结果 |
