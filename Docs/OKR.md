# StoryWeave（墨织）OKR

> 版本：v1.0  
> 更新日期：2026-10-18  
> 阶段：桌面版 MVP，写到可安装预览版  
> 关联：[产品需求](./PRD.md) · [技术选型](./TechStack.md) · [API](./API.md) · [数据模型](./DataModel.md) · [错误码](./Errors.md)

本阶段不设日活或留存。目标是一位作者能在本机把一部长篇的资料整理完，并且重启之后还在。

## Objective

作者能在不联网、不注册的桌面应用里，稳定整理一部长篇的人物、关系、故事线和章节。

## Key Results

| 编号 | 结果 | 怎样算完成 |
| --- | --- | --- |
| KR1 | 离线能建成一个小型项目 | 30 分钟内建出不少于 5 个人物、若干关系和两条故事线，全程不需要网络和账号 |
| KR2 | 重启不丢 | 档案、关系、图谱布局、事件顺序和章节正文在重新打开后都还在 |
| KR3 | 两种顺序都看得懂 | 故事内时间与章节叙述顺序可以不一致，时间线上两种信息同时可见 |
| KR4 | 坏文件进不来 | 用损坏的导入文件操作后，当前项目仍能打开，内容与导入前一致 |
| KR5 | 两套桌面系统能装上 | macOS 与 Windows 各完成一次真实安装、启动和上述保存验证 |

这些结果对应 [产品需求第 12 节](./PRD.md)。插件槽、远端仓库、模型和移动端不计入本阶段。

## 从哪里开始写

壳和命令一起做。页面只依赖仓库接口，桌面版的实现是 Tauri 命令，由 Rust 读写 SQLite。调用形状以 [API](./API.md) 为准，字段以 [数据模型](./DataModel.md) 为准。

页面顺序按依赖来，不按目录字母来：

1. **应用壳和项目库。** 顶栏、左侧导航、右侧详情、宣纸与夜墨，同时能新建并打开一个 SQLite 项目。
2. **概览。** 人数、关系数、事件数、未完成章节来自当前项目。新建人物、事件、章节会进入对应页并选中新建对象。
3. **人物。** 列表、按姓名和状态筛选、档案字段、删除前说明后果。
4. **关系图。** 节点和曲线来自同一份人物与关系。拖动只改布局。不能把人物连向自己。
5. **故事线与时间线。** 事件可以同时出现在多条故事线里。时间线用故事内排序，并标出首次出现在哪一章。
6. **章节与笔记。** 章节正文是 Markdown 原文，旁边是预览。笔记能被搜索命中。
7. **搜索、设置、快照。** 一个搜索框打开对象。设置页显示项目路径、主题和最近 10 份快照。自动保存约 0.8 秒合并一次。

关系图不要排在人物之前。没有人物，图上没有节点。章节不要排在事件之前。时间线需要事件已经存在。

本阶段不写这些页面：账号、同步、插件管理、模型对话、移动端布局。
