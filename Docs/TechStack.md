# 技术选型

> 版本：v1.0  
> 更新日期：2026-10-18  
> 状态：桌面版 MVP 已定，本机能力在 Tauri 进程内  
> 取舍说明见 [技术规划第 3 节](./Planning.md)

桌面版是单机软件。界面、数据库和项目文件都在作者的电脑上。本机能力是 Tauri 进程里的 Rust 命令，不另起服务，也不保存用户账号。

## 已定选型

| 层次 | 选型 | 这一版怎么用 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 窗口、菜单、文件对话框、安装包 |
| 本地能力 | Tauri 内的 Rust | SQLite、备份、命令参数校验。插件是进程内 trait，不加载动态库 |
| 界面 | Vue 3 + TypeScript + Vite | 页面与组件 |
| 路由与状态 | Vue Router + Pinia | 七个工作区页面，以及当前项目和保存状态 |
| 关系图 | Vue Flow | 自定义人物节点和关系边 |
| 正文 | CodeMirror 6 | Markdown 原文与并排预览。不做第二套所见即所得 |
| 样式 | CSS 变量 | 宣纸与夜墨两套主题。不并行引入 Tailwind |
| 校验 | Rust 领域规则 | 命令写入前检查空名称、自关系和顺序。界面展示返回的错误码 |
| 数据库 | SQLite | 每个小说项目一个库文件。应用自己的最近项目和主题另放一份应用库 |
| 标识与时间 | ULID 字符串，UTC ISO 8601 | 便于导出后再导入 |
| 包管理 | pnpm | 工程初始化时锁定 Node.js 当前 LTS |
| 测试 | Vitest，Rust 测试 | 先覆盖领域规则和仓库读写。界面关键路径再补 |
| CI | GitHub Actions | 与本地同一套检查 |

前端不拼接 SQL，也不把任意文件路径交给命令。页面只调用 [API](./API.md) 里的命令。

## 两个库，各管一件事

| 库 | 位置 | 内容 |
| --- | --- | --- |
| 应用库 | 应用数据目录里的 `app.sqlite` | 最近项目、主题、上次是否正常退出 |
| 项目库 | 作者能在设置里看到的那个文件 | 人物、关系、事件、故事线、章节、笔记、图谱布局 |

小说正文只进项目库。导出和备份复制的是项目库，不包含主题和最近项目列表。

## 明确不用

| 方案 | 原因 |
| --- | --- |
| 独立的 Go 或 FastAPI 服务 | 单机使用不需要本机端口和第二个进程 |
| 前端直接执行 SQL | 导入和删除规则会散落到页面里 |
| Tiptap 与 CodeMirror 同时做 | 正文只保留 Markdown 原文 |
| Tailwind 与 CSS 变量同时做 | 原型和主题已经用 CSS 变量写明 |
| 账号服务、托管同步 | 软件不保存用户信息 |

插件槽、作者自己的远端仓库、模型 Provider、移动端留到桌面版 MVP 之后。它们不改变上面的选型：仍然由本机命令访问本机数据。
